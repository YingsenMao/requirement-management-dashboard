## 1. 产品概述

### 1.1 产品定位

BreathCare WEB 是鱼跃医疗旗下的呼吸护理管理云平台，为呼吸治疗设备（呼吸机、制氧机）的经销商、医生和进口商提供设备管理、患者治疗数据监控、依从性分析和报告导出等功能。

### 1.2 目标用户

| 用户类型 | 典型场景 |
|---------|---------|
| 一级经销商（医疗机构/HME） | 管理下级组织、监控所有患者治疗数据、管理设备和医生 |
| 二级经销商 | 管理自有患者和设备、查看治疗数据 |
| 医生 | 查看分配的患者治疗数据、管理随访记录、导出报告 |
| 进口商 | 管理设备分配、变更设备归属组织 |

### 1.3 系统功能总览

```
BreathCare WEB
├── 登录与账户管理（登录、注册、密码重置、二次验证）
├── 工作台（数据总览、依从性分析、治疗数据分析、设备情况、使用情况）
├── 患者管理（患者列表、新增/编辑患者、治疗数据查看、报告导出、随访管理、自定义列）
├── 设备管理（设备列表、变更归属、参数设置、远程控制、数据推送、SIM 卡到期筛选与导出）
├── 组织管理（组织信息、下级组织、医院管理、医生管理、账号管理）
├── 报告管理（依从性报告、治疗报告、详细报告、随访报告）
├── 消息提醒（SIM 卡到期通知、铃铛 UI、跳转筛选）
└── 个人中心（账户信息、治疗信息设置、报告设置、修改密码）
```

### 1.4 多语言支持

系统提供 17 个语言包，界面可选切换 16 种语言：中文、英语、西班牙语、葡萄牙语、意大利语、法语、波兰语、泰语、越南语、日语、德语、希腊语、瑞典语、罗马尼亚语、捷克语、韩语。

- 2.1.12.0 新增韩语（ko-KR）

- 语言切换入口取决于帮助中心开关（见 3.8）：开关开启时，语言切换移入用户菜单弹窗；开关关闭时，保留顶部语言下拉即时切换

### 1.5 数据实体关系

系统共有 66 个数据实体，以**组织（Dealer）**为顶层租户进行数据隔离。以下为核心实体及其关系：

**核心实体关系图：**

```
└──────────────────────────────────────────────────────────────────┘
         │                    │                    │
         ▼                    ▼                    ▼
┌─────────────┐    ┌──────────────┐    ┌──────────────────┐
│  患者        │    │  设备         │    │  医生             │
│  (Patient)  │◄──►│  (DeviceInfo) │    │  (DoctorInfo)    │
│             │    │              │    │                  │
│ dealerCode  │    │ dealerCode   │    │ dealerCode(多对多)│
│ doctorId    │    │ patientId    │    │ hospitalId       │
│ deviceSn    │    │ deviceSn(PK) │    │ doctorId(PK)     │
└──────┬──────┘    └──────┬───────┘    └────────┬─────────┘
       │                  │                     │
       ▼                  ▼                     ▼
┌─────────────┐    ┌──────────────┐    ┌──────────────────┐
│ 设备绑定历史  │    │ 呼吸日数据    │    │  医院             │
│ (History)   │    │ (BreathDay)  │    │  (Hospital)      │
└─────────────┘    └──────────────┘    └──────────────────┘
       │                  │
       ▼                  ▼
┌─────────────┐    ┌──────────────┐
│  随访记录    │    │ 呼吸次数据    │
│  (FollowUp) │    │ (BreathEach) │
└─────────────┘    └──────────────┘
```

**核心实体说明：**

| 实体 | 表名 | 主键 | 说明 |
|------|------|------|------|
| 组织 | `tbl_dealer` | `dealerCode` | 经销商/医疗机构/进口商，支持自引用层级（最多 5 级） |
| 用户 | `tbl_user` | `id`(UUID) | 系统登录用户，关联组织，区分角色和账号类型 |
| 患者 | `tbl_patient` | `id`(UUID) | 患者信息，归属组织，关联主治医生和当前设备 |
| 设备 | `tbl_device_info` | `deviceSn` | 设备信息，以序列号为主键，归属组织，可绑定患者 |
| 医生 | `tbl_doctor_info` | `doctorId` | 医生信息，通过关联表与组织和医院建立多对多关系 |
| 医院 | `tbl_hospital` | `id`(UUID) | 医院信息，通过关联表与组织和医生建立多对多关系 |
| 设备绑定历史 | `tbl_patient_device_history` | `id`(UUID) | 记录患者与设备的绑定/解绑历史，含活跃期时间段 |
| 呼吸日数据 | `tbl_breath_day` | `id`(UUID) | 每日治疗数据汇总（AHI、漏气量、使用时长等） |
| 呼吸次数据 | `tbl_breath_each` | `id`(UUID) | 单次治疗会话数据（40+ 临床指标） |
| 随访记录 | `tbl_follow_up` | `id`(UUID) | 随访/干预记录，归属患者 |
| 患者标签统计 | `tbl_patient_tag_stat` | `(patient_id, window_days)` | 患者标签筛选预聚合数据，按 1/7/14/30/90 天窗口存储原始指标（使用天数、总分钟、平均 AHI/漏气/CAI、2-8 小时达标天数分桶），定时任务聚合 |
| 消息通知 | `tbl_notification` | `id`(BIGINT) | 按经销商维度的系统通知（当前仅 SIM_CARD_EXPIRE 类型），含标题、内容、到期设备数量、隐藏标记；定时任务每日零点扫描生成 |

**多对多关联表：**

| 关联表 | 实体 A | 实体 B | 说明 |
|--------|--------|--------|------|
| `tbl_dealer_doctor_map` | 组织 | 医生 | 组织与医生的关联关系 |
| `tbl_dealer_hospital_map` | 组织 | 医院 | 组织与医院的关联关系 |
| `tbl_doctor_patient_map` | 医生 | 患者 | 医生与患者的关联关系 |
| `tbl_doctor_hospital_map` | 医生 | 医院 | 医生可分配多家医院 |
| `tbl_patient_hospital_map` | 患者 | 医院 | 患者与医院的关联关系 |

**关键架构特征：**
- **多租户隔离**：几乎所有实体都携带 `dealerCode` 字段，组织为顶层租户
- **软删除**：所有核心实体支持软删除（`deleted` 字段）
- **审计时间戳**：标准 `createTime` / `updateTime` 自动填充
- **治疗数据层级**：BreathEach（单次会话）→ BreathEachDetailFull（完整详情，1:1）→ BreathEachCrossDay（跨日拆分，1:N）→ BreathDay（日汇总）
- **标签统计预聚合**：患者列表标签筛选基于 `tbl_patient_tag_stat` 预聚合表，定时任务每小时聚合（组织当地时间 0 点切窗），治疗日写入/绑定时间变更/解绑/切换默认设备时增量刷新

### 1.6 核心业务流程

#### 流程 A：设备生命周期

```
设备入库 ──> 分配到组织 ──> 绑定患者 ──> 设备上传数据 ──> 工作台聚合展示
(DeviceInfo   (dealerCode    (patientId    (BreathEach/     (DashboardData
 创建)         赋值)          赋值)         BreathDay)       定时聚合)
                                              │
                                              ▼
                                    解绑设备 / 变更归属 ──> 设备转移到新组织
                                    (活跃期结束)            (重新绑定新患者)
```

**关键节点：**
- 设备入库：DeviceInfo 创建，归属组织确定
- 绑定患者：创建 PatientDeviceHistory 记录，设置活跃期开始时间
- 数据上传：设备通过 IoT 平台上报数据，生成 BreathEach（单次）和 BreathDay（日汇总）
- 解绑：PatientDeviceHistory 活跃期结束，设备 patientId 清空
- 变更归属：设备 dealerCode 变更，可能伴随患者解绑

#### 流程 B：患者生命周期

```
创建患者 ──> 绑定设备 ──> 设备上传治疗数据 ──> 查看数据概览
(Patient     (DeviceInfo   (BreathEach/        (图表/报告
 创建)        patientId)    BreathDay)          展示)
    │                                            │
    ├──> 关联医生(DoctorPatientMap)               ├──> 导出报告(PDF)
    ├──> 分配医院(PatientHospitalMap)             ├──> 随访记录(FollowUp)
    └──> 设置数据共享                             └──> 解绑/删除
```

**关键节点：**
- 创建患者：Patient 创建，归属组织确定，可选绑定设备和医生
- 绑定设备：设备 SN 校验（组织归属/零售设备），冲突检测（活跃期重叠）
- 数据查看：基于 BreathDay/BreathEach 的治疗数据图表，按设备类型动态展示
- 报告导出：选择报告类型和时间范围，生成 PDF（本地下载或邮箱发送）
- 删除患者：仅经销商角色可操作，患者及关联数据软删除

#### 流程 C：组织层级与数据可见性

```
一级经销商创建 ──> 邀请下级组织(邮件) ──> 下级注册 ──> 设置查看权限
(Dealer创建,      (DealerInvitation      (Dealer       (parentViewPermission
 orgLevel=FIRST)   Record)               注册)          ENABLE/UN_ENABLE)
                       │
                       ▼
              关联医生(邮件) ──> 医生注册 ──> 分配医院 ──> 创建患者
              (DealerDoctorMap)  (DoctorInfo   (DoctorHospital  (Patient
                                  注册)         Map)             创建)
```

**数据可见性规则：**
- 上级组织可查看下级组织数据（需 `enablePatient=ENABLE` 且 `parentViewPermission` 授权）
- 医生只能查看关联的患者数据
- 进口商只能查看设备数据，无患者数据权限
- 患者数据共享设置控制医院内医生的可见范围

#### 流程 D：治疗数据流

```
设备端采集 ──> 上报 BreathEach ──> 聚合 BreathDay ──> 聚合 DashboardData
(呼吸机/       (单次治疗会话,      (每日汇总,          (工作台看板,
 制氧机)        40+临床指标)        AHI/漏气/时长)      定时任务聚合)
                    │                    │                    │
                    ▼                    ▼                    ▼
              BreathEachDetail     报告生成(PDF)        依从性计算
              Full(完整详情)        (按类型组合)         (Clinical/Statistical)
```

**数据粒度：**
- **BreathEach**：单次治疗会话（通常一晚一次），包含 40+ 临床指标
- **BreathEachCrossDay**：跨日会话拆分（如 23:00 开始次日 07:00 结束）
- **BreathDay**：日汇总，按患者+设备+日期聚合
- **PatientTagStat**：患者标签统计预聚合，按患者 × 窗口（1/7/14/30/90 天）聚合 BreathDay 数据，支撑患者列表标签筛选与工作台异常人数统计（同一 SQL 口径）
- **DashboardData**：工作台看板数据，定时任务预聚合（依从性、治疗分析、设备情况）

### 3.1 登录与账户管理

#### 3.1.1 登录

**登录表单字段：**

| 字段 | 说明 | 验证规则 |
|------|------|---------|
| 账号 | 用户名 | 必填 |
| 密码 | 登录密码 | 必填，密码在传输中加密 |
| 验证码 | 图形验证码 | 必填，验证码有效期 290 秒，点击可刷新 |

**登录前置条件：**
- 必须勾选同意《用户协议》
- 如需签署 DPA 协议，需额外勾选同意《DPA 协议》

**二次验证（邮箱验证码）：**

当系统检测到以下情况时，会触发二次验证：
1. **长时间未登录**：系统向用户绑定邮箱发送 6 位数字验证码
2. **登录位置变更**：系统向用户绑定邮箱发送 6 位数字验证码
3. **无绑定邮箱**：用户需手动输入邮箱地址，接收验证码后完成验证

**登录后的角色路由：**
- 医生 → 患者列表页
- 进口商 → 设备列表页
- 其他角色 → 工作台

- 自动补全仅返回**当前用户所属组织**的设备（经销商用户返回本组织的设备；医生用户返回其关联的所有经销商组织的设备）
- 编辑模式下，已绑定的设备 SN 不可修改（只读）

**零售设备流程（仅医生新增患者时）：**

当医生输入的设备 SN 不属于其关联的任何经销商组织时：
1. 系统在全局设备库中查找该 SN
2. 若设备存在：弹出确认对话框"所添加设备 SN {0} 不属于您所属组织，请确认后继续操作"
3. 确认后进入零售设备模式：所属医院选择被隐藏、信息共享强制设为"不共享"、自动选择当前医生
4. 取消确认：SN 字段被清空
5. 若设备在全局也不存在：SN 字段被静默清空
6. 后端独立判定设备是否为零售设备（跨组织设备标记为 IS_RETAIL），零售设备可绕过经销商归属校验
7. SN 错误频率限制：30 天内输入无效 SN 次数超过限制后，系统将阻止继续操作

**设备绑定时间冲突检测：**

提交表单时，若同时填写了设备 SN 和绑定时间，系统执行冲突检测：

1. **自动解绑**：若设备当前被其他患者绑定，系统先自动解除原绑定
2. **历史活跃期冲突检测**：查询该设备最近一条其他患者的绑定历史记录

| 冲突类型 | 条件 | 处理方式 |
|---------|------|---------|
| **类型 A（活跃期重叠）** | 新绑定时间落在其他患者的活跃期内 | 弹出确认对话框，用户确认后系统将截断原患者的活跃期结束时间为新绑定时间前一天，治疗数据重新分配给新患者 |
| **类型 B（时间早于原绑定）** | 新绑定时间早于或等于其他患者的绑定时间 | 弹出提示对话框，**阻止提交**，用户必须重新选择更晚的绑定时间 |

类型 A 确认后的数据处理：
- 原患者的活跃期结束时间设为新绑定时间 - 1 天
- 从新绑定时间起的治疗数据（呼吸日、呼吸次）重新分配给新患者
- 设备的绑定时间更新为新绑定时间

**可见性：** 仅报销开关开启的部署（日本站点及测试环境），按钮文案"导出报销报告"（日语"月別レポートのエクスポート"）。同一开关同时控制列表"近 1/2/3 月均使用时长"3 列的显示。

**统计窗口：** 最近 3 个完整自然月（上上月 1 日 ~ 上月末），每患者每设备统计：
- 月平均使用时长 = 月总使用分钟 / 当月天数
- 月内单日使用 ≥4 小时的天数（4 小时阈值固定）
- 月份早于设备首次绑定时间 → 显示"未开始"（日语"未開始"）

**算定リスク（报销资格风险）：**

| 口径 | 判定规则 | 风险等级 |
|------|---------|---------|
| 口径 1（月均使用时长） | 3 个月中"月均使用 <1h"的月数 | 0=无风险、1=风险低、2=风险高、3=算定不可 |
| 口径 2（≥4h 天数） | 3 个月中"≥4h 天数 <20 天"的月数 | 同上 |
| 不适用 | 任一月份"未开始"或有效月 <3 | 新規患者（N/A） |

**Excel 结构（单 sheet，12 列）：** 患者名 / 患者 ID / 设备 SN / 设备型号 / 医疗机构名（前 5 列）+ 算定リスク（月均使用时长）+ 3 个月 × 2 列（每月：平均使用时长、4 小时以上使用天数）。表头日/英双语；平均时长格式日语 `x時間y分`，其他 `xhy m`。文件名 `yyyyMMdd_JapanReimbursement.xls`。

### 3.9 消息提醒

**可见角色：** 除医生外的所有角色（一级经销商管理员/普通、下级经销商管理员/普通、进口商）

消息提醒是一个系统级通知功能，当前仅包含"SIM 卡即将到期"一种通知类型。

#### 3.9.1 铃铛 UI

**位置：** 导航栏右侧，语言区域左侧

**交互：**
- 铃铛图标 + 未读数量徽章（超过 99 显示 "99+"）
- 点击铃铛展开下拉面板，显示通知列表
- 每条通知显示：消息内容、创建日期（格式 `dd/MM/yyyy`）、更多操作（隐藏）
- 点击通知项跳转到设备列表页，自动携带 `simCardExpireFilter=EXPIRE_6_MONTHS` 筛选参数
- 点击"隐藏"后通知不再显示（`hidden=true`），未读数量同步更新
- 点击面板外部自动关闭

#### 3.9.2 通知生成规则

**定时任务：** 每天零点（`0 0 0 * * ?`）执行

**扫描逻辑：**
1. 遍历所有经销商
2. 对每个经销商，查询未来 6 个月内到期的 SIM 卡数量（`expiration_time <= 当前时间 + 6 个月`）
3. 若数量 > 0 且当天该经销商尚无同类型通知，则生成新通知：
   - 类型：`SIM_CARD_EXPIRE`
   - 标题：`SIM卡即将到期提醒`
   - 内容：`您有{N}台设备的流量卡即将到期，请及时处理`
   - 扩展字段：到期设备数量
4. 若数量 = 0，不生成通知

**数据模型：** `tbl_notification` 表，按经销商维度存储，支持隐藏标记（`hidden`），无软删除

#### 3.9.3 后端 API

| 接口 | 方法 | 说明 |
|------|------|------|
| `/notification/unreadCount` | GET | 获取当前经销商未隐藏通知数量 |
| `/notification/list` | GET | 获取当前经销商未隐藏通知列表（按创建时间降序） |
| `/notification/hide/{id}` | POST | 隐藏指定通知（设置 `hidden=true`） |

所有接口需认证，按当前用户所属经销商过滤数据。

## 4. 业务规则

### 4.1 依从性计算规则

**Clinical（临床）：** 依从性 = 使用时长 ≥ 阈值的天数 / 患者实际使用天数

**Statistical（统计）：** 依从性 = 使用时长 ≥ 阈值的天数 / 选择区间总天数

**过去 N 天依从性：**
- 设备绑定时间在 N 天内：依从性 = 使用时长 ≥ 阈值的天数 / 绑定至今的天数
- 设备绑定时间在 N 天外：依从性 = 使用时长 ≥ 阈值的天数 / N

**可配置阈值：**

| 阈值 | 设置角色 | 范围 | 默认值 |
|------|---------|------|--------|
| 使用时间阈值 | 一级/下级经销商管理员 | 2-8 小时 | 4 小时 |
| 依从性合规阈值（天数比例） | 一级/下级经销商管理员 | 60/70/80/90/100% | 70% |
| 漏气量阈值 | 一级/下级经销商管理员 | 0-30 L/min | 30 |

**补充规则：** 窗口内无使用数据的患者依从性 = 0，计入不合规。

### 4.2 设备状态

| 状态 | 说明 |
|------|------|
| 在线 | 设备已连接网络 |
| 离线 | 设备未连接网络 |
| 未启用 | 设备尚未激活 |

### 4.3 设备类型

| 类型 | 说明 |
|------|------|
| 单水平 (CPAP) | 单水平呼吸机 |
| 双水平 (BiPAP) | 双水平呼吸机 |
| 全自动双水平 | 全自动双水平呼吸机 |
| 便携式 (Pocket) | 便携式呼吸机 |

### 4.4 通讯方式

非联网、WiFi、2G、NB、4G、5G、蓝牙

### 4.5 疾病类型

阻塞性睡眠呼吸暂停 (OSA)、中枢性睡眠呼吸暂停 (CSA)、混合性睡眠呼吸暂停 (MSA)、其他

### 4.6 治疗数据异常判定

| 指标 | 异常判定 |
|------|---------|
| AHI 异常 | 使用日平均 AHI > 30 |
| 漏气量异常 | 使用日平均漏气量 ≥ 漏气量阈值（默认 30 L/min） |
| 依从性不合规 | 依从性 < 依从性合规阈值（默认 70%） |

### 4.6.1 患者标签统计预聚合规则

- 预聚合表按"患者 × 窗口（1/7/14/30/90 天）"存储原始指标（不存判定结果）：有无数据、使用天数、总分钟、平均 AHI/漏气/CAI、2~8 小时达标天数分桶
- 窗口定义：`[组织当地今天00:00 − N天, 组织当地今天00:00)`，右开，N 个完整日历日
- 定时聚合：每小时触发（cron `0 5 * * * ?`），仅在组织当地时间 0 点执行窗口切换聚合（实际约 00:05 执行）
- 增量刷新触发条件：
  - 治疗日数据写入后刷新该患者全部窗口
  - 绑定时间变更时按相同规则刷新
  - 解绑设备后刷新预聚合（避免列表挂旧设备）
  - 切换默认设备后按新默认设备刷新预聚合
  - 无主数据推送回写绑定段起点后按绑定时间变更刷新
  - 变更归属仅迁移组织编码不重算
- 阈值动态适配：只存原始指标，组织修改使用时长阈值/依从率阈值后筛选结果立即变化，无需重跑批处理
- 工作台治疗数据分析的三项异常人数与患者列表标签筛选同一 SQL 口径，保证跳转前后结果一致

### 4.7 设备绑定规则

- 每个患者最多绑定 2 台设备（后端可配置上限）
- 绑定时间早于今日时，设备历史数据自动同步至该患者
- 修改绑定时间会影响依从性计算的准确性
- 解绑设备后，患者历史数据保留但不再接收新数据
- 变更设备归属时，若目标为进口商类型，必须先解绑患者
- **使用天数口径：** 当前默认设备有治疗数据的天数（治疗日去重计数，含 SD 卡导入历史数据），不再按患者创建时间截断

**设备归属校验：**
- 经销商用户：只能绑定本组织的设备，非本组织设备将被拒绝（"经销商无效"）
- 医生用户：可绑定其关联经销商的设备；跨组织设备走零售设备流程
- 零售设备可绕过经销商归属校验

**设备解绑规则：**

| 场景 | 处理方式 |
|------|---------|
| 单个解绑 | 确认对话框 → 后端检查设备是否正在使用中 → 正在使用则阻止解绑（提示"操作失败，该患者正在使用设备"） |
| 批量解绑 | 确认对话框 → 后端检查所有选中患者 → 正在使用设备的患者被过滤 → 弹出二次确认"患者：{姓名}正在使用设备，无法解绑。是否继续解绑其它设备？" → 仅解绑非使用中的设备 |

### 4.8 设备变更归属规则

**单个变更归属流程：**

1. 勾选设备 → 选择目标组织 → 选择是否解绑患者 → 提交
2. 后端预检查返回 4 种结果：

| 检查结果 | 处理方式 |
|---------|---------|
| 无异常 | 直接执行变更 |
| 存在绑定患者的设备（且目标为进口商） | 弹出二次确认：需下载绑定设备 SN 列表，确认解绑后执行变更。解绑状态自动强制为"解绑" |
| 存在绑定多台设备的患者 | 变更被阻止：提示下载文件查看设备，需先手动解绑或加入变更设备 |
| 存在零售设备 | 变更被阻止：提示下载文件查看设备 SN |

**解绑选项可见性：** 当前用户或目标组织为进口商时，"是否解绑"选项隐藏（进口商无患者管理权限）

**批量变更归属：** 通过上传 Excel 文件批量操作，预检查逻辑与单个变更一致

**数据迁移：** 变更归属（不解绑迁移组织）时，除单次治疗数据外，呼吸日数据（`tbl_breath_day`）与设备状态日志（`tbl_device_state_log`）的组织编码一并迁移至新组织，并刷新患者标签统计

### 4.9 数据共享规则

- 经销商创建患者时：可选择将患者信息共享给所属医院的所有医生
- 医生创建患者时：可选择将患者信息共享给所属医院的所有医生
- 选择"共享"：患者信息对该医院所有医生及所属组织成员可见
- 选择"不共享"：仅被选中的医生及所属组织成员可查看

### 4.10 登录安全规则

**验证码：** 图形验证码有效期 290 秒（4 分 50 秒），过期后输入框获焦时自动刷新

**用户协议与 DPA 协议：**
- 登录前必须勾选同意《用户协议》
- 系统根据用户状态判断是否需要签署 DPA 协议（数据处理协议），未签署时显示 DPA 勾选框
- 系统检查用户是否已同意最新版本的协议，若协议有更新则弹出"协议更新提示"阻断登录
- 用户勾选同意 DPA 后，系统记录"勾选签署"标识（用于保留主动同意的签署证据）

**二次验证（邮箱验证码）：**
- 登录接口返回状态码 201 时触发二次验证
- 触发原因：长时间未登录（类型 1）或登录位置变更（类型 2）
- 有绑定邮箱：显示脱敏邮箱地址，发送 6 位数字验证码，60 秒后可重发
- 无绑定邮箱：用户需手动输入邮箱地址后接收验证码
- 验证码仅接受数字输入

**密码重置：**
- 输入账号后失焦自动查询绑定邮箱，若有邮箱则自动填充且不可编辑
- 重置请求发送后，用户需在邮箱中点击链接完成重置
- 重置链接有有效期，过期后显示"链接已超时"

### 4.11 组织层级规则

- 组织层级最多 5 级，达到上限后无法继续创建下级组织
- 新建下级组织时通过邀请邮件注册，注册后自动建立上下级关系
- 编辑下级组织时邮箱不可修改（邮箱为组织唯一标识）
- 组织类型为进口商时，查看权限中"查看设备与患者"选项被禁用（进口商无患者管理权限）
- 删除下级组织将永久删除其所有关联数据（患者、设备、医生），需二次确认

### 4.12 医生关联规则

- 关联医生时系统向医生邮箱发送关联请求邮件
- 邮件链接有效期 48 小时，过期后需重新发送
- 若邮箱已注册：医生点击链接后自动完成关联
- 若邮箱未注册：医生点击链接后需先完成注册，之后自动关联
- 可为一个医生分配多家医院
- 调整医生所属医院后，若医生不再属于原医院，则无法继续查看原医院的患者信息
- 解除关联需二次确认

### 4.13 批量导入/导出规则

**批量导入患者：**
- 文件格式：仅支持 .xls/.xlsx，不超过 5MB
- 同一患者不支持导入多台设备
- "跳过已绑定的设备进行导入"选项：勾选后已绑定设备将被跳过
- 导入完成后自动下载结果文件

**批量导出患者：**
- 批量导出通过邮箱发送，约 30 分钟后查收
- 邮箱为必填项，支持格式校验
- 邮箱地址在多次导出间自动记忆
- "导出全部"携带当前列表筛选条件（含标签组合）查询后导出
- 导出 Excel 新增"依从性类型"动态列（表头含组织阈值，见 3.3.6）
- 异步导出按请求语言填充单元格内容

| **OHI** | Obstructive Hypopnea Index | 阻塞性低通气指数 | 每小时阻塞性低通气事件次数 |
| **SI** | Snore Index | 鼾声指数 | 每小时检测到的鼾声事件次数 |
| **RERA** | Respiratory Effort-Related Arousal | 呼吸努力相关微觉醒 | 因呼吸努力增加导致的睡眠微觉醒，不满足呼吸暂停或低通气标准 |
| **FL** | Flow Limitation | 气流受限 | 上气道部分阻塞导致吸气流量波形变平，提示气道阻力增加 |
| **ODI** | Oxygen Desaturation Index | 氧减指数 | 每小时血氧下降≥3%（或4%）的次数 |

### A.2 疾病分类

| 缩写 | 英文全称 | 中文名称 | 说明 |
|------|---------|---------|------|
| **OSA** | Obstructive Sleep Apnea | 阻塞性睡眠呼吸暂停 | 最常见的睡眠呼吸暂停类型，由睡眠时上气道物理阻塞引起 |
| **CSA** | Central Sleep Apnea | 中枢性睡眠呼吸暂停 | 由大脑未能向呼吸肌发送正确信号引起 |
| **MSA** | Mixed Sleep Apnea | 混合性睡眠呼吸暂停 | 同时包含阻塞性和中枢性呼吸暂停事件 |

### A.3 AHI 严重程度分级

| 等级 | 中文 | AHI 范围 |
|------|------|---------|
| Normal | 正常 | < 5 次/小时 |
| Mild | 轻度 | 5-15 次/小时 |
| Moderate | 中度 | 15-30 次/小时 |
| Severe | 重度 | > 30 次/小时 |

### A.4 治疗模式

**单水平模式：**

| 模式 | 英文全称 | 中文名称 | 说明 |
|------|---------|---------|------|
| **CPAP** | Continuous Positive Airway Pressure | 持续气道正压通气 | 在整个呼吸周期中提供单一恒定压力以保持气道开放 |
| **APAP** | Automatic Positive Airway Pressure | 自动气道正压通气 | 根据患者需求在设定范围内自动逐次调节压力 |

**双水平模式：**

| 模式 | 英文全称 | 中文名称 | 说明 |
|------|---------|---------|------|
| **S** | Spontaneous | 自主呼吸模式 | 设备提供两个压力水平（IPAP/EPAP），患者自主触发所有呼吸 |
| **T** | Timed | 时间控制模式 | 设备按设定频率送气，不依赖患者自主呼吸 |
| **ST** | Spontaneous/Timed | 自主/时间模式 | 结合 S 和 T 模式：患者可自主呼吸，但设备在频率低于设定值时提供备用频率 |
| **VGPS** | Volume Guaranteed Pressure Support | 容量保证压力支持 | 自动调节压力支持以达到目标潮气量 |
| **Auto S** | Auto Spontaneous | 自动自主模式 | S 模式的自动版本，EPAP 根据检测到的事件自动调节 |

**高级模式：**

| 模式 | 英文全称 | 中文名称 | 说明 |
|------|---------|---------|------|
| **ASV** | Adaptive Servo-Ventilation | 适应性伺服通气 | 持续调节压力以稳定呼吸模式，主要用于中枢性睡眠呼吸暂停 |
| **PCV** | Pressure Control Ventilation | 压力控制通气 | 按设定压力和频率送气，用于较重症的护理场景 |

### A.5 压力参数

| 缩写 | 英文全称 | 中文名称 | 说明 |
|------|---------|---------|------|

| **Pmax** | Maximum Pressure | 最大压力 | 设备提供的最高压力（APAP/自动模式） |
| **Pinit** | Initial Pressure | 初始压力 | 治疗开始时的起始压力 |
| **Pset** | Treatment Pressure | 治疗压力 | 固定 CPAP 模式下的处方治疗压力 |
| **P90** | 90th Percentile Pressure | 第90百分位压力 | 90% 的送气压力低于此值，用于评估治疗充分性 |
| **L90** | 90th Percentile Leak | 第90百分位漏气量 | 90% 的漏气值低于此值，用于评估面罩贴合质量 |

### A.6 呼吸周期参数
